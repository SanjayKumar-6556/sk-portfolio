## Overview

A consolidated surface where platform owners see who consumes which models, how spend trends, and where incidents cluster — without granting everyone raw warehouse access.

## The Problem

Logs existed, but narrative threads across retries, model versions, and feature flags lived in five tabs. Leaders asked basic questions that engineers answered with bespoke SQL.

## Architecture

ETL lands aggregates into Postgres; Next.js renders authenticated views with row-level guards per team. Grafana handles infra graphs; product semantics stay in-app.

## Key Engineering Challenges

### Attribution without PII leaks

Hashed actor IDs and coarse-grained team buckets preserved usefulness while staying policy-safe.

### Drill-down latency

Materialized views refreshed incrementally; heavy explorations pushed to async exports.

### Change management

Dashboard version pins tracked alongside API releases so regressions were obvious.

## Workflows / Pipelines

1. Ingest billing + router logs nightly.
2. Normalize dimensions (team, route family, model SKU).
3. Serve summaries + guard APIs for CSV exports.

## Stack & Infrastructure

Next.js App Router, Postgres, background workers for rollup refresh.

## Results & Metrics

Finance reviews shortened because engineering and GTM shared one vocabulary for AI spend drivers.

## What I'd Do Differently

Ship anomaly detection cards earlier — humans spotted spikes late.
