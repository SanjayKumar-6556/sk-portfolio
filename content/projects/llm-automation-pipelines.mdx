## Overview

A durable execution layer for LLM-heavy workflows: ingest events, fan out to typed steps, persist partial state, and surface actionable traces when models misbehave.

## The Problem

Ad-hoc scripts in notebooks worked for prototypes but collapsed under spikes, partial failures, and audit questions about who approved what.

## Architecture

Event-driven workers backed by a transactional store. Each step declares schema for inputs/outputs; the runner validates, executes, and checkpoints. Human review is modeled as first-class states, not side-channel email.

## Key Engineering Challenges

### Partial failure semantics

Retries had to be safe when steps were non-idempotent. Versioned inputs and compensating actions made reruns boring instead of dangerous.

### Token and latency SLAs

Adaptive batching and model routing tables separated latency-sensitive paths from offline enrichment.

### Evaluation hooks

Dogfood harnesses replay production traces into staging prompts when schemas change.

## Workflows / Pipelines

1. Event lands with correlation ID.
2. Planner expands DAG from template version.
3. Steps execute with timeouts + structured logging.
4. Terminal states emit webhooks + metrics.

## Stack & Infrastructure

Python services, Redis for leases, Postgres for truth, OTLP exporters for traces.

## Results & Metrics

On-call pages dropped after traces linked failing prompts to exact upstream payloads.
