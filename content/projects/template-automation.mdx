## In one line

The team's bulk-mail tool took its content from Google Sheets, and someone had to produce each
template and paste it into the right sheet by hand. I built the app that generates the templates
and the automation that puts them where the mail tool expects them, so the whole path runs
end to end.

**Skills demonstrated:** internal tool design, full-stack delivery (Next.js frontend, FastAPI
backend), third-party workflow integration, removing manual steps from a recurring process.

## Context

Internal work at Nestack Technologies, where I have been an AI engineer since March 2025.

Campaign sending ran through an existing bulk-mail tool that reads its content out of Google
Sheets. That gave the team a workflow with a human bottleneck in the middle of it: write the
template somewhere, then copy it into the correct sheet, in the correct shape, for every
campaign. It is the kind of step that is individually trivial and collectively expensive — it
scales linearly with campaign count, it is easy to get subtly wrong, and it cannot run
unattended.

## What I built

- A **template-generation application** with a Next.js frontend and a FastAPI backend, so
  producing a template is a first-class operation with a UI rather than a document someone edits
  by hand.
- **Automation of the sheet-insertion step**, so a generated template lands in the spreadsheet
  the bulk-mail tool reads from, in the structure that tool expects — closing the loop between
  generation and sending.

## Why it was built this way

The constraint that mattered most was that the bulk-mail tool was not mine to change. It reads
from Google Sheets and that was fixed. So the design question was not "what is the ideal campaign
system" but "where can automation be inserted without asking anyone to change the tool they
already rely on". Building around the existing sheet contract meant the team's sending workflow
did not have to be renegotiated in order to get the manual step removed.

Splitting the app into a Next.js frontend over a FastAPI backend kept the generation logic
callable independently of the UI, which is what made automating the insertion path possible
rather than bolting a script onto a form.
